# Cookbook

The cookbook collects small, practical solutions to recurring tasks. Each recipe focuses on one job and calls out the behavior that can surprise you. Examples target the documented Alaco 0.2.0 standard library; check the [compatibility reference](/reference/compatibility) before using target-specific APIs.

## Count until a condition changes

Use `loop (while condition)` when the number of iterations depends on a value:

```aco
fn main() {
    let mut attempts = 0;
    loop (while attempts < 3) {
        attempts += 1;
    }
    println(attempts); // 3
}
```

The condition is checked before each iteration. Ensure the body can eventually make it false; this loop form does not provide a documented `break` statement.

## Read a command-line option

Use `std.args` for a small CLI with a value-taking option and a flag:

```aco
import std.args;

fn main() {
    let output = args.option("--output", "result.txt");
    if args.has_flag("--verbose") {
        println("Verbose output enabled");
    }
    println("Output: " + output);
}
```

Both `--output result.txt` and `--output=result.txt` are accepted. Call `option` before reading positional arguments: registering a value-taking option tells the positional helper not to count its value as a positional argument. This is a lightweight parser, not a complete command-line schema or help generator.

## Distinguish a missing environment variable from an empty one

`env.get` returns an empty string when the variable is missing. Use `env.has` when that distinction matters:

```aco
import std.env;

fn main() {
    if env.has("APP_MODE") {
        println("APP_MODE=" + env.get("APP_MODE"));
    } else {
        println("APP_MODE is not set");
    }
}
```

Environment changes made with `env.set` affect only the current process; they cannot modify the parent shell.

## Check a JSON property, including `null`

Use `json.is_null` to distinguish a present JSON `null` from a missing key. Use typed getters for values of the expected type:

```aco
import std.json;

fn main() {
    let payload = "{\"name\":\"Alaco\",\"nickname\":null,\"enabled\":true}";
    if json.is_valid(payload) {
        let name = json.get_string(payload, "name", "unknown");
        let enabled = json.get_bool(payload, "enabled", false);
        let nickname_is_null = json.is_null(payload, "nickname");
        println(name);
        println(enabled);
        println(nickname_is_null);
    }
}
```

These helpers access top-level object properties; they do not expose a dynamic JSON tree or recursively traverse nested objects. A typed getter returns its fallback when the property is missing or has another JSON type.

## Make an HTTP request and inspect its status

Prefer a structured response over the body-only helper when an empty response body must be distinguished from failure:

```aco
import std.http;
import std.json;

fn main() {
    let result = http.response("https://example.com/health");
    if json.is_valid(result) {
        let status = json.get_int(result, "status", 0);
        let success = json.get_bool(result, "success", false);
        let error = json.get_string(result, "error", "");
        if success {
            println("HTTP status: ${status}");
        } else {
            eprintln("Request failed (${status}): " + error);
        }
    } else {
        eprintln("The HTTP helper did not return a valid response object");
    }
}
```

The response JSON includes `status`, `body`, `success`, and `error`. A status of `0` means no HTTP response was obtained. JavaScript output requires `curl` on `PATH`; native Unix builds other than macOS require OpenSSL development files for HTTP support. Do not send secrets to endpoints you do not trust.

## Write a file without silently ignoring failure

Filesystem writes return `Bool`. Check the result rather than assuming the write succeeded:

```aco
import std.fs;

fn main() {
    if fs.write_text("output.txt", "Generated by Alaco\n") {
        println("Wrote output.txt");
    } else {
        eprintln("Could not write output.txt");
    }
}
```

Relative paths are resolved from the process's current working directory. `write_text` truncates an existing destination, so do not use it on a path whose contents must be preserved.
